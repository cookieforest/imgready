What GIF costs you, and what PNG gives back

GIF dates from 1987 and carries two hard limits that PNG does not. The first is colour: a GIF can hold a maximum of 256 distinct colours in its palette. Any photograph saved as GIF has already been quantized down to that palette, which is why gradients in GIFs show banding and dithering speckle.

The second is transparency. GIF supports only 1-bit transparency — each pixel is either fully opaque or fully invisible, with nothing in between. That is why GIF logos often have jagged, aliased edges: there is no way to store a half-transparent pixel to smooth the boundary. PNG stores a full 8-bit alpha channel, so edges can be genuinely soft.

An important caveat about quality

Converting to PNG removes those limits for future edits, but it cannot undo damage already done. If a photograph was flattened to 256 colours when it was saved as GIF, those colours are gone permanently — the PNG will faithfully reproduce the banded, dithered version. Similarly, jagged 1-bit edges stay jagged; PNG simply stores them losslessly.

What you gain is a file that will not degrade further, that every editor handles properly, and that can hold smooth transparency for anything you add from here.

Animated GIFs export a single frame

PNG is a still-image format, so there is no way to represent an animation in it. When you convert an animated GIF, you get its first frame as a still PNG. That is usually what people want — a thumbnail, a poster image, or a frame to edit — but it is worth being explicit, because it is a common surprise.

If you want to keep the animation, do not convert to PNG. Convert GIF to WebP instead: animated WebP preserves motion and is typically far smaller than the GIF. If you want a specific frame rather than the first one, the editor's frame tools let you pick from an animated GIF before exporting.

PNG file size may go up

Do not be alarmed if the PNG is larger than the GIF. GIF's 256-colour palette is itself a form of aggressive compression, and PNG storing the same image losslessly at full colour depth can cost more bytes. If size matters more than losslessness, convert to WebP, which usually beats both.

When this conversion is the right call

Three situations. Editing: you need to work on a GIF asset in a proper editor without the palette getting in the way. Transparency quality: you are placing a GIF logo on a coloured background and the hard 1-bit edges look wrong, so you want a PNG you can re-cut with soft alpha. Archiving a still: you want a lossless copy of a frame that will not degrade with further saves.

For simply serving the image on a website, PNG is rarely the best final answer — WebP is smaller for almost all content. Use PNG as the working format and export the delivery format from it.

Frequently asked questions

What happens to an animated GIF?

You get its first frame as a still PNG, because PNG cannot store animation. If you want to keep the motion, convert the GIF to WebP instead — animated WebP preserves the animation and is usually much smaller than the original GIF.

Will converting to PNG improve the image quality?

It prevents further loss but cannot undo existing loss. If the image was reduced to 256 colours when it became a GIF, that banding and dithering is permanent and the PNG will reproduce it faithfully. What you gain is a lossless, fully editable file with room for smooth transparency going forward.

Why is my PNG bigger than the GIF?

Because GIF's 256-colour palette is itself a strong form of compression, while PNG stores the image losslessly at full colour depth. This is normal. If file size matters more than losslessness, convert to WebP, which is usually smaller than both.

Is GIF transparency preserved?

Yes. GIF's 1-bit transparency (each pixel fully opaque or fully invisible) is carried into PNG's 8-bit alpha channel. Existing hard edges stay hard, but the PNG can now hold genuinely soft transparency for any edits you make.

Can I pick a different frame instead of the first?

Yes — open the image in the editor, which provides frame tools for animated GIFs, and export the frame you want. The straight conversion always takes the opening frame.

Are my files uploaded anywhere?

No. Decoding and encoding happen locally in your browser through WebAssembly. Nothing is transmitted, which you can verify in the Network tab of your browser's developer tools.
