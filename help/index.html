When it does not work

Help

Everything here runs on your own device, which means the failures look different from a normal web app. Nothing is queued on a server, so there is nothing to wait for and nothing we can retry for you. These are the things that actually go wrong.

A file will not open

It is a HEIC or HEIF from an iPhone

No browser except Safari can decode HEIC on its own, so imgready fetches a decoder the first time you drop one. It is a big download. On a slow connection the first HEIC can sit there for a few seconds before anything happens, and the ones after it are instant because the decoder is cached.

If it fails outright, reload the page once and try again so the decoder can be fetched cleanly.

It is a RAW file, like CR2, NEF or ARW

Not supported, and not planned. RAW is camera-specific and each maker does it differently. Export a JPG, TIFF or HEIC from your photo app first.

It is a PDF

Not an image format, so it will not load here. Export the page you want as PNG or JPG first.

The file is fine everywhere else

Check the extension matches the actual contents. A file renamed from .webp to .jpg is still a WebP, and some apps will open it anyway while a strict decoder will not. Renaming it back usually fixes it.

The tab froze

Compression happens in your browser using your own memory, so a very large image or a very large batch competes with everything else the machine is doing. A server-based tool hides this by making it someone else's problem; the trade for not uploading your files is that the work happens here.

Three things help, in order: drop fewer files at once, close other heavy tabs, and use a laptop rather than a phone for a big batch. If one specific file kills the tab every time, it is usually enormous in pixel dimensions rather than in megabytes, so resize it before compressing.

The output looks wrong

My transparent PNG has a white background now

JPG cannot store transparency. Anything see-through has to become a solid colour, and that colour is white. If you need transparency, convert to WebP, AVIF or PNG instead.

The colours shifted slightly

Usually an embedded colour profile. Images saved from professional tools can carry a profile that browsers handle differently from desktop software. The pixel data is intact; the interpretation changed.

My SVG came out blurry or the wrong size

SVG is vector, so it has no natural pixel size. Converting to PNG or JPG has to pick one. Set the width you want in the resize field before converting rather than scaling the result up afterwards.

The file got bigger, not smaller

Already-compressed images have nothing left to remove, and re-encoding adds overhead. This is common when converting a small JPG to PNG, which is lossless and stores every pixel. Check that the output format suits the image: photos want JPG, WebP or AVIF, flat graphics want PNG.

Nothing downloads

Downloading a batch triggers several saves at once, and browsers sometimes block that after the first one. Look for a blocked-download notice in the address bar and allow it for this site. Downloading the batch as a ZIP avoids the problem entirely.

Browser support

Current Chrome, Edge, Firefox and Safari, on desktop and mobile. The tool needs WebAssembly and a modern Canvas, so Internet Explorer and very old Android browsers will not work. Private windows are fine. Extensions that block scripts will stop it, because the whole tool is a script.

Checking the privacy claim yourself

Do not take our word for it. Open your browser developer tools, go to the Network tab, and drop a file. You will see the page load and, the first time, a decoder download. You will not see a request carrying your image, because there is not one.

Still stuck

Email hello@imgready.app with the format you were converting from and to, the rough file size, and your browser. If a specific file fails, saying which format it came out of is usually enough to identify it. Do not send the file itself.
