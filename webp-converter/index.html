What WebP is, and why every modern site is using it

WebP is an image format developed by Google in 2010, derived from the same VP8 video compression technology behind YouTube. After a decade of slow adoption, WebP support became universal in 2020 when Safari added it. Today every major browser — Chrome, Edge, Firefox, Safari, Samsung Internet, Opera — opens WebP natively, which means you can serve WebP as your primary image format with zero compatibility concerns for any visitor whose browser is less than five years old.

The reason to switch is straightforward: WebP produces files that are typically 25–35% smaller than the equivalent JPG at the same visible quality, and 26% smaller than the equivalent PNG with full alpha-channel transparency support. On a content-heavy website or a product catalogue, that's a CDN bill cut and a measurable improvement to Core Web Vitals.

Lossy vs lossless WebP

WebP supports both modes. Lossy WebP is what you want for photographs — same quality semantics as JPG, but smaller. Lossless WebP is what you want for screenshots, logos, illustrations, and anything that used to be a PNG — same pixel-perfect fidelity, but smaller. imgready picks the right mode automatically: quality 100 produces lossless WebP, quality 1–99 produces lossy WebP. The default is 82, the universal sweet spot.

Browser support and serving WebP safely

Chrome, Edge, Firefox, Safari and Samsung Internet have full WebP support. The only "browsers" that don't are Internet Explorer (long deprecated) and very old versions of Android stock browser. If you need to support those, the safest approach is the HTML <picture> element, which lets you list a WebP source first and a JPG/PNG fallback second. The browser picks the first format it can decode:

<picture>
  <source srcset="/images/photo.webp" type="image/webp">
  <img src="/images/photo.jpg" alt="..." width="1200" height="800">
</picture>

For a <picture> fallback set, generate the WebP first, then run the same image again with JPG selected.

When NOT to convert to WebP

  • Email attachments. Many email clients and corporate inbox preview tools still don't decode WebP. Send JPG instead.
  • Print-quality archives. WebP at quality 100 is lossless but most professional print pipelines still expect JPG or TIFF. Keep your archival masters in their native format.
  • Animated GIFs. WebP can do animation (animated WebP), but the encoder support is more limited. For a quick share, GIF or MP4 is still safer.
  • Embedded in older PDF generators. Some PDF libraries don't yet handle WebP. Test before deploying at scale.

How imgready encodes WebP

imgready uses Google's reference WebP encoder (libwebp), compiled to WebAssembly via the jsquash library. This is the same encoder Squoosh uses and the same encoder runs inside Chrome itself when it serves WebP. On non-iOS platforms, imgready can also fall back to the browser's native canvas WebP encoder for speed; on iOS Safari, where the native encoder has known quality issues, imgready always uses the WebAssembly encoder for consistent output.

Frequently asked questions

Is WebP supported by all browsers?

Yes — every major browser (Chrome, Edge, Firefox, Safari, Samsung Internet, Opera) has supported WebP since 2020. The only browsers that don't are Internet Explorer and very old Android stock browsers.

How much smaller are WebP files compared to JPG?

Typically 25–35% smaller at the same visible quality. The exact savings depend on the image content — high-detail photographs save less, flat illustrations and screenshots save more.

Can WebP have transparency like PNG?

Yes. WebP has a full alpha channel. WebP-lossless is typically 26% smaller than the equivalent PNG with identical pixel-perfect transparency.

What's the difference between lossy and lossless WebP?

Lossy WebP is what you want for photographs — smaller files at the cost of imperceptible quality loss. Lossless WebP is what you want for screenshots and graphics — smaller PNG-equivalent files. imgready picks based on the quality slider: 100 = lossless, 1–99 = lossy.

Should I serve WebP to old browsers with a JPG fallback?

If you support browsers older than 2020 (Internet Explorer, very old mobile), use the element with a WebP source and JPG fallback. For newer audiences, just serving WebP directly is fine.

Does imgready convert HEIC iPhone photos to WebP?

Yes. imgready decodes HEIC/HEIF in-browser using a JavaScript decoder, then re-encodes as WebP. This is the most space-efficient way to share iPhone photos on any modern website.
