Why image optimization matters

Images account for 60–80% of average website data transfer. A single uncompressed photo can be 3–5 MB — larger than your entire HTML, CSS, and JavaScript combined. Large images cause:

  • Slow Largest Contentful Paint (LCP): Google's ranking metric. Large hero images delay LCP by 2–4 seconds, hurting SEO and user experience.
  • High bounce rate: Users leave sites taking over 3 seconds to load. Mobile users especially.
  • Bandwidth waste: Serving uncompressed images wastes 70% of bandwidth that could serve actual content.
  • Mobile bloat: Large image files consume precious mobile data and battery.

The good news? Optimizing images is the highest-ROI performance fix. Most sites can cut image size by 60–80% with zero visual difference, cutting overall site size by 40–60%.

Rule of thumb: If it's a photo, use WebP (JPEG fallback). If it's a graphic or has text, use PNG. If it's a logo or icon, use SVG. Everything else uses MP4 or WebP video.

Dimension targets by use case

Hero images (large background or featured image): 1200–1600px wide. On mobile, load a smaller version (800px). Use responsive images with srcset to serve the right size automatically.

Product images (e-commerce): 600–800px wide for thumbnails, 1200px for detail view. Compress both sizes separately to match bandwidth.

Blog post images: 800–1000px wide, matching your content width. Never wider — wastes pixels off-screen.

Thumbnails: 300–400px wide. These can be much smaller and more compressed (quality 70) without noticeable loss.

Icons and logos: Use SVG. If you must use raster (PNG), 100–200px is enough.

Responsive images: serving different sizes

Modern web design requires serving different image sizes to different devices. Use HTML srcset to tell the browser which image to load:

<img srcset="hero-800.webp 800w, hero-1200.webp 1200w" sizes="100vw" src="hero-1200.jpg" alt="...">

The browser loads hero-800.webp on mobile (saving 60% bandwidth) and hero-1200.webp on desktop. This is the most important optimization for real-world performance.

Format adoption: WebP and AVIF in 2026

WebP: 97% browser support. Use as default for all photographs. Serve JPEG fallback in <picture> tags for older browsers.

AVIF: 70% browser support (Chrome, Firefox, Android). Better compression than WebP (50–60% of JPEG size), but no support in Safari or iOS. Use for maximum performance if you can provide WebP/JPEG fallbacks.

JPEG: 100% support, but outdated. Still useful for fallback, but always serve WebP first.

PNG: 100% support. Use for graphics, never for photos.

Frequently asked questions

What format is best for web images?

WebP is best for photographs (25–35% smaller than JPEG with equivalent quality, supported by 97% of browsers). Serve JPEG as fallback via tags. For graphics and logos, use PNG or SVG. PNG is lossless; SVG is infinitely scalable and smallest. Always match format to content type.

What size should web images be in KB?

Hero images: 60–100 KB. Product images: 30–80 KB. Blog images: 40–80 KB. Thumbnails: 15–30 KB. Icons and logos: 5–20 KB. Every image should be under 200 KB for fast load. Smaller is always better — aim for 50 KB or less if visual quality permits.

How do I reduce image file size without losing quality?

Compress aggressively: set JPEG quality to 75–80 (quality 80 cuts size 60–75% with zero visible loss). Use WebP for 25–35% additional reduction. Resize dimensions first — a 4000px image resized to 1200px is already 75% smaller. Combine all three methods for maximum reduction.

What is WebP and should I use it?

WebP is a modern format compressing to 25–35% of JPEG size with better quality. Supported by 97% of browsers (all modern browsers). Always serve WebP to modern browsers and JPEG to older ones via tags. WebP is essential for web performance — Google officially recommends it.

What is lazy loading and does it help?

Lazy loading defers loading off-screen images until the user scrolls near them. Add loading='lazy' to every tag. Cuts initial page load by 30–50% if you have many images. Works on all modern browsers. Combine with image compression for maximum performance improvement.

What is LCP and how do images affect it?

Largest Contentful Paint (LCP) is the time to display the largest visible element (usually a hero image). Google uses LCP as a Core Web Vital ranking factor. Large uncompressed images delay LCP, hurting both user experience and search rankings. Compress images to 50–100 KB to achieve good LCP.
