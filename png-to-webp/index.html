PNG → WebP: the silent default for the modern web

If you're publishing on the web and you have PNGs, converting to WebP is almost always a good idea. WebP supports both a lossless mode (drop-in replacement for PNG, typically 26% smaller) and a lossy mode (drop-in replacement for JPG, typically 25–35% smaller, with full alpha). Modern browsers all decode WebP natively. The trade-off is essentially zero — there is no quality penalty in lossless WebP, and lossy WebP at quality 82 is visually indistinguishable from the source for almost all real-world content.

Lossy or lossless?

  • Lossy WebP (quality 1–99). The right choice for photographs. Even iPhone screenshots that contain photos in the background compress better as lossy WebP. Default and recommended for most web use.
  • Lossless WebP (quality 100). The right choice for screenshots of UI, logos, icons, line art, anything with sharp edges or where you cannot lose any pixel. Replaces PNG-24 directly.

When PNG to WebP is the wrong answer

  • You need to support pre-2020 browsers (Internet Explorer, very old Android). Generate the WebP first, then run the same PNG again with JPG selected and serve both via the <picture> element.
  • The destination is print or email. Many of those pipelines still expect PNG or JPG. Stay with PNG.
  • You need a tiny indexed-color PNG-8. For very flat illustrations and icons, PNG-8 with quantization can be smaller than WebP-lossless. imgready's Compress PNG path handles that case.

Setting up a PNG fallback

If you support older browsers and want to serve WebP with a PNG fallback:

<picture>
  <source srcset="/logo.webp" type="image/webp">
  <img src="/logo.png" alt="..." width="240" height="80">

Upgrading from WebP to AVIF

WebP beats PNG on file size, but AVIF beats WebP by a further 20–30%. If you're optimizing images for maximum web performance, the logical next step after WebP is AVIF. Use imgready's WebP to AVIF converter or convert directly from PNG to AVIF with the PNG to AVIF tool.

Converting transparent PNG to WebP

WebP supports transparency (alpha channel), so converting a transparent PNG to WebP preserves the transparency. The resulting WebP will render correctly anywhere WebP is supported. If you're targeting a context that doesn't support WebP (older Outlook, some CMS editors), keep the original PNG as a fallback. For web use in a <picture> element, transparent WebP with a PNG fallback is the recommended approach in 2026.

Frequently asked questions

Will the transparency survive the conversion?

Yes. WebP has a full alpha channel that is preserved through both lossless and lossy modes.

Is WebP-lossless really smaller than PNG?

Yes — typically 26% smaller for the same pixel-perfect content. The savings come from WebP's more efficient compression algorithm, not any quality loss.

Should I use lossy or lossless for screenshots?

For UI screenshots with text and sharp edges, lossless. For screenshots of photographs (e.g. screenshotted Instagram posts), lossy at quality 82 produces dramatically smaller files with no visible difference.

Will old browsers display WebP?

Modern browsers since 2020 all support WebP. For older browsers (Internet Explorer, very old Android), serve a PNG fallback via the element.

Is PNG to WebP private?

Yes. Everything happens in your browser. No upload.

How is this different from a PNG optimizer like TinyPNG?

PNG optimizers shrink PNG files but stay in PNG format. WebP conversion replaces PNG with a different (smaller, better-compressing) format. For a typical web image you'll save more by converting to WebP than by optimizing a PNG.
