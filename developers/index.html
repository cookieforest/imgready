Quickstart — SDK

Three steps, no account needed.

1

Add the script tag to your page

Paste this into your HTML, just before the closing </body> tag.

HTML
<!-- imgready SDK -->
<script src="https://imgready.app/sdk/imgready-sdk.js"></script>
2

Compress an image file

Pass any image File or Blob — from a file input, drag-and-drop, or clipboard paste. Get back a compressed Blob ready to upload or display.

JavaScript — basic usage
// Compress a single image to WebP at quality 82
const result = await imgready.compress(file, {
  format:  'webp',
  quality: 82
});

// result is a Blob — download it, upload it, display it
const url = URL.createObjectURL(result);
const a = document.createElement('a');
a.href = url;
a.download = 'photo.webp';
a.click();
3

That's it

No API keys, no accounts, no server. The SDK lazy-loads its encoders (WebP, AVIF, HEIC) only when needed — no impact on page load for formats you don't use.

Common use cases

Copy-paste examples for the most common integration patterns.

Compress on file input change (e.g. profile photo upload)
const input = document.querySelector('input[type="file"]');

input.addEventListener('change', async () => {
  const file = input.files[0];
  if (!file) return;

  const optimized = await imgready.compress(file, {
    format:  'webp',
    quality: 82,
    maxDim:  1200  // resize longest side to 1200px
  });

  // Upload the optimized blob instead of the original
  const formData = new FormData();
  formData.append('photo', optimized, 'photo.webp');
  await fetch('/api/upload', { method: 'POST', body: formData });
});
Batch compress a folder of images
const files = [...input.files]; // FileList → Array

const results = await imgready.compressAll(files, {
  format:  'webp',
  quality: 80,
  maxDim:  1600
});

// results is an array of Blobs, same order as input
results.forEach((blob, i) => {
  console.log(`File ${i+1}: ${(blob.size/1024).toFixed(1)} KB`);
});
Convert iPhone HEIC photos to WebP (unique to imgready)
// HEIC files from iPhone drop events or file inputs
// are decoded automatically — no extra setup needed

const heicFile = input.files[0]; // e.g. IMG_4821.HEIC

const webp = await imgready.compress(heicFile, {
  format:  'webp',
  quality: 82,
  maxDim:  1200
});
// webp is a Blob ready to display or upload
Remove attribution badge with a license key
// Call init() once at the top of your app
// with the license key emailed to you after purchase.
imgready.init({
  licenseKey: 'IR-D-1a2b3c4d5e6f7890-abcd1234'

// All subsequent compress() calls inherit the key

All options

Every parameter accepted by imgready.compress(file, options)

OptionTypeDefaultDescription
formatstring'webp'Output format: webp, avif, png, jpg, gif
qualitynumber821–100. At 100 PNG is lossless; below 100 PNG uses indexed color (PNG-8). JPG/WebP/AVIF are always lossy.
maxDimnumber0Resize longest side to this value in px. 0 = no resize. Aspect ratio always preserved.
cropstring'none'Crop from center: none, 1:1, 4:3, 3:4, 16:9, 9:16
licenseKeystringnullYour license key. Removes the "Optimized by imgready" footer badge. Auto-emailed after purchase below; contact us if you need it resent.

How license validation works

Short version — for technical buyers wondering if they can trust the system.

  • Each key is signed with HMAC-SHA256 against a server-side secret. Keys cannot be forged from the SDK source.
  • On imgready.init(), the SDK calls our verification endpoint exactly once. Result is cached in localStorage for 24 hours, so subsequent page loads are instant and offline-tolerant.
  • The verification call is a single POST to our Cloudflare Worker, returns in milliseconds, and contains only the key — never image data, never user data. Privacy policy covers this in detail.
  • If verification fails (bad key, network outage, server down), the badge stays visible — the SDK is fail-safe, never fail-open. Your image processing continues uninterrupted; only the attribution display is gated.
  • Personal-tier keys are domain-bound on request — tell us the domain at purchase or after, and the key will only validate on that origin. Developer and Commercial keys are unrestricted across your project portfolio.
  • Lost your key? Email hello@imgready.app from the address you used at purchase — we'll look it up in our records and resend.

Frequently asked questions

Is the imgready SDK free?

The SDK is free to use with the imgready attribution badge visible. A paid licence removes the badge and is available via Ko-fi.

What formats does the SDK support?

WebP, AVIF, JPG, PNG, and GIF output. HEIC and TIFF input via optional lazy-loaded decoders. The SDK exposes the same encoder pipeline as the imgready UI.

Can I use imgready in a Node.js or server environment?

No — the SDK relies on the browser's Canvas API and WebAssembly runtime. It is a client-side only library. For server-side image processing, consider sharp or libvips.

Where is the SDK documentation?

Full API reference, options object, and code examples are on this page. The SDK is also available as an ES module import — see the Quickstart section above.

Does the SDK work with React, Vue, Angular, and other frameworks?

Yes. The SDK works in any framework — React, Vue, Angular, Svelte, or plain HTML/JavaScript. It's a simple async function that takes a File or Blob and returns a Blob. No dependencies, no framework lock-in.

What's the bundle size impact of the SDK?

The main SDK script is ~2 KB minified. WebAssembly encoders (WebP, AVIF, HEIC) are lazy-loaded on demand, adding ~1.5 MB each only when needed and cached after first use. Pages using only PNG/JPG output have zero encoder overhead until a user actually compresses.
